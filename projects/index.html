Independent personal project

Messenger Archive & Semantic Search

Search text and transcribed audio by meaning in a private message archive.

Independent personal project. The diagram describes software components and contains no example messages or account records.

Engineering details
Engineering Context
A personal project that separates message import, transcription and indexing so each step can be retried.
Architecture
Rust loads message records through MTProto. PostgreSQL stores records and transcription jobs. A Python worker runs Whisper, and a Rust indexer stores embeddings in Qdrant. An MCP interface exposes search.
Technical Challenges
  • Parallel workers can encounter jobs that another worker already claims.
  • The vector store and the indexing checkpoint are separate systems.
Design Decisions
  • Use PostgreSQL row-level locks with FOR UPDATE SKIP LOCKED to let workers skip conflicting rows.
  • Map each vector upsert to a deterministic UUIDv5 ID.
  • Advance the index checkpoint after the vector write succeeds.
Reliability Considerations
  • A retry can repeat a vector write to the same point ID. Unrelated side effects need their own deduplication.
  • A crash between stages can leave work to replay. Progress is tracked at each completed stage.
What the project does
  • Combines message and transcript search in an MCP interface.
Technology stack
  • Rust
  • Python
  • MTProto
  • PostgreSQL
  • Whisper
  • Qdrant
  • MCP

EntityLocker — Row-Level Entity Concurrency Utility

Explore how Java threads can coordinate by an entity key within one process.

Public source and JUnit tests for a Java locking experiment maintained by Denis Stepulenok. Source repository

Engineering details
Engineering Context
EntityLocker is an independent Java utility with JUnit cases for several locking behaviours.
Architecture
A concurrent map associates entity IDs with reentrant lock objects. A thread-local value records the current acquisition order and rejects a lower nested ID. Registry removal is attempted when a critical section exits.
Technical Challenges
  • Nested key acquisition can create dependency cycles.
  • Retiring a key safely requires coordination with both current holders and contenders.
Design Decisions
  • Use one ordered key type and reject decreasing acquisitions on the same thread.
  • Keep the lock registry inside each EntityLocker instance.
Reliability Considerations
  • Tests cover same-key access, reentrancy, timeouts and rejection of decreasing lock order.
  • Registry retirement needs additional stress testing. Separate instances or processes do not share these locks.
What the project does
  • Illustrates JVM-local keyed locking and why safe reclamation needs separate verification.
Technology stack
  • Java
  • ConcurrentHashMap
  • ReentrantLock
  • JUnit

Independent public repository

RustShot Desktop Capture

Capture screenshots across different desktop environments with a common command-line interface.

Public RustShot capture guide and source maintained by Denis Stepulenok. Source repository

Engineering details
Engineering Context
RustShot is an independent Rust utility for Windows, Linux and macOS.
Architecture
Platform-specific adapters acquire an image and send it to the requested output destination. Linux Wayland can use the desktop portal. Windows also supports screen recording.
Technical Challenges
  • Operating systems expose different capture capabilities.
  • Desktop portal workflows depend on the caller’s desktop session and permissions.
Design Decisions
  • Document platform support separately for screenshots, region selection and recording.
  • Keep capture and output handling separate.
Reliability Considerations
  • Repository tests cover capture helpers and output behaviour. Live desktop checks depend on the platform.
What the project does
  • Provides screenshot capture on three desktop platforms and documents their feature differences.
Technology stack
  • Rust
  • Desktop capture APIs
  • Image processing
