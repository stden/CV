Work project

Secure Document Link Gateway

Time-limited, encrypted links to documents stored on a remote system.

Engineering context: Kuehne+Nagel, iOPM (work)

Problem

Users and business applications need access to documents that stay on a remote system, for a limited time, without the gateway keeping per-request state.

Architecture

A link service issues AES-GCM encrypted links. Each link carries its own expiry and the original URL. A background downloader fetches documents into a local store, a stateless gateway decrypts the link and streams the file, and scheduled jobs clean up expired documents.

Architecture diagram

  1. Business application. The caller; it never receives the remote document location.
  2. Link service. Creates links. The expiry is part of the encrypted link.
  3. PostgreSQL. The record of issued links, used by background jobs.
  4. Background downloader. Runs outside the request path.
  5. Local file store. The cache that background jobs keep consistent.
  6. Link gateway. Stateless: it validates the link itself and needs no database lookup.
  7. Scheduled jobs. Keep the cache consistent with link lifetimes.

Component names are generic. Concepts used here: security, cache consistency, distributed coordination.

Technology stack

  • Java 17
  • Spring Boot
  • PostgreSQL
  • AES-GCM

Technical challenges

  • Keeping the file cache consistent with link lifetimes across several schedulers, without per-request state.

Design decisions

  • Each link carries its own expiry and is AES-GCM encrypted, so the gateway can serve files without a database lookup.
  • Background jobs, not request handlers, fetch documents and remove expired files.

Reliability considerations

  • The expiry time is part of the encrypted link, so a link is refused after it expires even if cleanup has not run yet.
