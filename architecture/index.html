Engineering concepts

Idempotency

Repeating an operation has the same effect within a defined boundary. A stable key can prevent duplicate records without covering unrelated effects.

Eventual Consistency

Separate stores may disagree while updates are in progress. Retries and reconciliation can help them converge when the changes are applied.

Message Delivery Guarantees

At-least-once delivery can repeat a message. Exactly-once processing requires a clearly defined transaction and effect boundary.

Failure Handling

Recover from transient faults through bounded retries, and expose persistent failures for inspection or replay.

Distributed Coordination

Threads in one JVM can share a lock. Multiple processes need a coordination mechanism with its own failure model.

Cache Consistency

Cached data can become stale. Expiry, invalidation and refresh policies determine when it becomes consistent with its source.

Observability

Logs, metrics and traces help explain behaviour and investigate failures.

Security

Use authentication, authorisation, appropriate data handling and a documented threat model to protect access.
