Rust and Model Context Protocol (MCP) for Local Archive Retrieval

Structuring read-only stdio MCP tools in front of a hybrid lexical and vector retrieval index so coding or research agents inspect narrow evidence without exfiltrating raw archives.

Based on independent personal archive experimentation and public modules in stden/pythorust_tg.

Why Expose Narrow Read-Only Tools Instead of Raw File Access

Giving an LLM agent unrestricted filesystem or database access mixes unrelated personal records into context windows and increases accidental leakage.

A narrow read-only MCP tool contract (search metadata filters, top-k chunk retrieval with explicit source IDs, and bounded payload size) enforces least privilege at the boundary.

Separating Indexing from Deterministic Query Execution

Hybrid retrieval pairs exact keyword filters with dense vector similarity so proper nouns and identifiers do not disappear in semantic-only matching.

Keeping ingestion idempotent and schema-validated ensures incremental updates do not corrupt existing embeddings or citations.

Engineering Trade-offs

  • Local stdio MCP servers avoid hosting credentials or exposing public network endpoints, while trading away remote multi-user sharing.
  • Chunk size optimization balances citation precision against surrounding conversational context.

Limitations & Boundaries

  • Independent personal tooling without public retrieval recall/precision benchmark datasets.
  • No personal archive records, prompts, or private identifiers are published.
